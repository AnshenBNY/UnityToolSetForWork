# UnityToolSetForWork

面向美术与特效制作的 Unity 编辑器工具。当前验证版本：Unity 2022.3.30f1c1。

入口：**BjTools → 多功能电饭煲**，窗口标签同名。

## 使用流程

1. 在左侧选择“复制与迁移 / 检查与修复 / 批量编辑”下的工具。
2. 预制体复制页添加一个或多个预制体，点击“预览复制内容…”或“预览复制 N 个预制体…”，查看分类清单。其他工具使用各自的“预览”按钮。
3. 预制体复制页点击“开始复制”；其他工具点击“执行预览中的更改”。执行按步骤分帧推进，可在步骤之间取消。
4. 所有工具的预览、执行操作和结果统一放在窗口底部的可折叠抽屉中。生成预览后自动展开，点击标题可收起；收起后仍显示状态摘要，各页签及复制模式保留各自的展开状态。复制页抽屉内显示输出位置、分类数量、副本名称和引用警告；“查看文件明细”支持筛选、分页及查看完整路径，共享资源与“操作记录”默认折叠。

预览后选择、参数、源文件、目标文件或相关 .meta 发生变化时，需要重新预览。普通问题会跳过对应项并允许执行其余更改；可能造成错误结果的问题会明确标为“阻断”。失败或取消会恢复本次已记录的修改。

## 各工具的改动

| 工具 | 行为 |
| --- | --- |
| 预制体复制 | 支持批量添加多个预制体，合并依赖并去重复制，统一保留源文件中的子资源 fileID。支持粒子全部 Mesh 槽与权重、Shape 网格、蒙皮网格、UI 贴图、材质、动画、Timeline、音频以及模型导入器的外部引用。 |
| 贴图迁移 | 预先保留所有目标路径，区分不同来源的同名贴图；先复制并导入，再更新材质。无须修改的材质不会计为失败。 |
| 依赖记录检查 | 候选限制同名、相同扩展名；移动过的根资源按 GUID 解析当前位置。修复后复查文件、更新状态与统计，重新解析也会验证修复结果。扫描包含 JSON 中记录的中间依赖及导入器 .meta 引用。 |
| 非法引用查询 | 选择单个文件时以其所在目录为归属范围；源扫描也应用排除规则；支持筛选与分页。 |
| 引用修复 | 只改 Unity 文本对象引用，校验 GUID、fileID 和资源类型。子资源存在歧义时阻止执行。清空引用写入真正的 `{fileID: 0}`。 |
| 批量重命名 | 按路径稳定排序，支持起始序号和位数；预检非法名称、重名及目标占用；资源通过临时名称分两阶段改名，保持 GUID。Hierarchy 模式过滤 Project 资源。 |
| 预制体与材质映射 | 源对象保持原样；按相对路径匹配目标；支持根节点及不同 Renderer 类型；保留预制体属性覆盖和局部变换；仅在同名节点来自同一预制体时跳过。 |
| 模型导入设置 | 仅应用勾选的参数组；补齐来源 Avatar；校验无效误差值、自身 Avatar 引用和缺失 Avatar；备份导入器 .meta。 |

## 预制体复制与保存

“完整复制”和“场景实例加工”是两个独立工作区，各自保留最近一次预览或结果，切换时不会互相覆盖。从 Project 选择一个或多个预制体后点击“添加 Project 中选中的预制体”，或直接把它们拖入列表区域。列表支持移除、清空和分页；重复项自动跳过，非 .prefab 资源及场景实例会明确提示未添加。源列表按项目保存，旧版的单个源预制体设置会自动迁入列表。

多个预制体各自生成副本，无须先放到场景的空物体下再另存临时预制体。本批次共用的材质、贴图、FBX、嵌套预制体等只复制一份，多个副本继续共用这些新资源；后续修改共用资源会影响使用它的副本。选中的预制体同时作为另一个预制体的嵌套资源或变体基类时，也只生成一个对应副本，并更新这些关系。

完整复制默认写入 Prefabs、Materials、FxMaterials、Meshes、Textures、ImageText、Animations、Audio 分类目录；只创建实际使用的目录。同名文件自动添加编号，重复执行会生成新的副本。

脚本、Shader、包内资源、未支持的资源类型及排除目录中的资源保留共享引用，并在预览中列出。TMP 字体等自定义 ScriptableObject 默认属于共享资源；“完整复制”按工具支持的资源类型处理，不能理解为复制项目中的所有类型。

副本在执行完成时已保存。结果中列出每个源预制体与副本名称，可分别定位或放入场景；“定位全部副本”选中本批次的根副本，“将全部副本放入场景”创建各自独立的实例，自动填入场景实例列表并切换到“场景实例加工”，一次 Ctrl+Z 可撤销这次批量放入。

完整复制清单按整批实际资源文件去重，一份文件显示一次，不把建目录、导入和更新引用算成不同资源。默认显示每个根副本的输出名称与分类数量；文件明细可展开，同名冲突的自动编号会单独提示。完成后分别显示预制体副本数量和已保存的资源总数。修改源列表、输出或排除目录后需重新整理清单。

整批复制作为一次文件操作备份。任何一个请求复制的根预制体无效或被排除时，整批阻止执行；中途失败或取消会恢复整批已记录的文件变化。成功后“恢复上次文件操作”经二次确认可恢复整个批次，场景实例仍需单独撤销。

复制完成后发现仍引用本应替换的原资源（包括粒子 Mesh 槽）时，保留整批副本并显示引用警告，不再因此回滚。结果摘要显示警告数量，明细列出引用方副本、当前仍引用的原资源以及对应资源副本，可分别定位；“复制操作记录”也包含这些信息。此时副本尚未完全独立，修改原资源仍可能影响副本。FBX 内嵌材质等导入时生成的引用可能不在 YAML 或 .meta 对象引用中，因此无法只靠文本 GUID 替换处理。文件复制/导入失败、根预制体无法加载和用户取消仍按原规则回滚。排除目录、脚本、Shader 等原本计划共享的资源继续单独列在“沿用现有资源”，不算残留引用警告。

切换到“场景实例加工”，从 Hierarchy 多选预制体根实例后点击“添加 Hierarchy 中选中的实例”，或拖入场景列表。Project 资源、普通物体和 Prefab 编辑模式中的对象不加入此列表。重复实例只保留一次，父实例和它内部的嵌套实例同时选中时，仅保留父实例，嵌套内容随父实例处理。

“复制材质…”“复制粒子材质…”“复制粒子网格…”“复制 Image / Text 资源…”“复制 MeshFilter 网格…”“复制动画与 Timeline…”均处理场景列表中的全部实例。每次模块操作共用一套资源副本，清单列出全部处理对象，取消在当前实例处理结束后生效。成功后一次 Ctrl+Z 可撤销整批场景引用修改（资源文件保留）；失败或取消同时恢复整批场景引用、原有预制体覆盖和新建文件。场景列表不跨窗口重开或脚本重载保存。

“保存到当前预制体”支持任意有效的场景预制体根实例，不依赖完整复制流程，也不判断实例是否由工具生成。保存会直接更新实例当前连接的预制体资源，与资源复制使用的输出目录无关。多个实例连接到同一个预制体时会阻止保存，需只保留其中一个，避免不同修改相互覆盖。嵌套对象的覆盖保存在各自根预制体中，不会递归 Apply 或解包共享子预制体，保存不会顺带保存无关的脏资源。批量保存失败会还原文件，并保留保存前尚未写入文件的场景修改。

## 其他工具操作指南

以下操作沿用统一的清单确认与执行流程。

### 依赖记录检查

#### 用途

将源工程资源依赖导出为 JSON，再在目标工程解析，快速定位丢失依赖与目录变化，并支持候选修复与报告导出。

#### 推荐流程

1. 在 `1) 目标选择` 中添加目录/资源（支持拖拽与“添加当前Selection”）
2. 在 `2) 导出配置与保存` 里设置规则后导出 JSON
3. 在目标工程中载入 JSON 并 `解析并检查依赖`
4. 对丢失项搜索候选并按需修复

#### 导出配置说明

- 引用存档自动排除 `Packages/` 下的包资源，无须手动添加排除目录；勾选“包含 Unity 内建依赖”也不会包含包资源。
- `包含 Unity 内建依赖`：通常不建议勾选
- `排除 Editor 目录资源`
- `排除扩展名`（逗号分隔）
- `JSON 文件名前缀`
- `排除目录规则`
- `JSON输出目录` 可浏览/恢复默认
- 导出按钮：
  - `保存到输出目录(JSON)`
  - `另存为(JSON)...`

#### 解析检查说明

- 可通过 `记录文件(TextAsset)` 或 `选择JSON文件` 指定记录
- 点击 `解析并检查依赖`
- 结果统计包含：总依赖 / 存在 / 丢失 / 内建
- 已验证的修复计入“存在”，卡片显示“已修复”；勾选“仅显示丢失项”后不再显示这些条目。
- 可选：
  - `仅显示丢失项`
  - `候选显示上限`
  - `修复仅限 JSON 记录范围（推荐）`
  - `修复时扩展扫描根对象依赖链`

#### 丢失项处理

- `为丢失项搜索候选资源`
- `导出丢失报告(CSV)`
- `导出丢失报告(JSON)`
- 在卡片内可：
  - 查看引用来源并 `跳转`
  - 对候选资源 `Ping`
  - `使用该候补修复`

修复先生成预览，执行完成后复查扫描范围内是否仍有旧 GUID 引用、目标资源及 fileID 是否有效。部分文件无法修改时，不会把整项标为已修复。再次解析、重开工具或移动资源后会重新验证；恢复备份或删除候选资源会重新报错。

JSON 限定范围以该条目的引用根对象为准。勾选“扩展扫描根对象依赖链”时，同时检查当前依赖链和 JSON 中属于这些根对象的中间文件，避免依赖链中断后漏扫。引用来源缺失的旧记录会使用 JSON 的根对象列表。文本资源和导入器 `.meta` 中的对象引用均可修复，支持引用换行、字段顺序变化及省略 `type`；资源自身的 GUID 和普通 GUID 文本不会被替换。

旧版本已完成的修复没有本地修复记录：工具仅在旧 GUID 对象引用已消失、当前根对象依赖链实际引用唯一同名资源且 fileID 有效时将其识别为已修复。仅搜索到同名候选不会视为修复成功。找不到可改写引用时，预览会提示检查扫描范围、文件移动和二进制格式。

### 非法引用查询

#### 用途

扫描指定对象中的“越界依赖引用”（引用到不应依赖的外部资源），并提供定位与修复动作。

#### 操作步骤

1. 在 `查询对象` 添加要扫描的目录/文件（支持拖拽与 Selection）
2. 在 `忽略规则` 配置：
   - 是否排除 `Editor` 目录
   - 排除扩展名（如 `.cs,.dll,.asmdef`）
   - 排除目录列表
3. 点击 `开始查询`
4. 在结果卡片中处理每条非法引用

#### 支持处理动作

- `查找候选替换`
- `预览清空引用`（执行后清空对象引用）
- `复制到目标目录并替换`
- 对候选执行 `替换为此资源`

---

### 贴图复制迁移

#### 用途

扫描目标材质目录引用的贴图，复制到指定输出目录，并回写材质中的贴图引用。

#### 操作步骤

1. 选择 `待修改的材质目录`
2. 选择 `贴图输出目录`
3. 可选：添加 `排除目录`（这些目录下贴图不会复制）
4. 点击 `预览贴图迁移`
5. 在下方确认复制与修改范围后点击 `执行预览中的更改`，完成后查看执行结果。

---

### 批量重命名

#### 用途

批量修改资源文件名或 Hierarchy 节点名。

#### 作用对象

- `资源文件`（Project 选中）
- `Hierarchy节点`（Hierarchy 选中，可选“包含子节点”）

#### 重命名方式

- `基础名称加序号`（格式：`新基础名_序号`）
- `替换部分字符串`
- `插入字符串`（开头/结尾/指定位置）

#### 操作步骤

1. 先在 Unity 中选中目标
2. 在工具里设置作用对象与命名规则
3. 点击 `预览重命名`
4. 在下方确认原名、新名与处理范围，再点击 `执行预览中的更改`。

---

### 材质预制体映射

#### 用途

将源根节点中的预制体映射/材质映射到目标根节点对应结构，适合同骨架或同层级对象的批量替换。

#### 功能项

- `复制嵌套特效预制体`：按相对路径在目标节点挂载对应预制体
- `映射所有 Renderer 的材质（包含根节点）`：按相对路径把源 Renderer 材质赋值给目标

#### 操作步骤

1. 指定 `源根节点` 与 `目标根节点`
2. 勾选需要执行的映射项（可同时勾选）
3. 点击 `预览映射`，检查目标节点与资源。
4. 点击 `执行预览中的更改`。

> 源对象保持原样，目标必须是场景对象；不会解包源预制体，目标修改支持 Unity Undo。

---

### 批量修改模型导入设置

#### 用途

对当前选中的模型资源（如 FBX）批量应用导入参数。

#### 配置组（可独立开关）

- `材质导入设置`：Material Import Mode
- `动画误差设置`：
  - Animation Rotation Error
  - Animation Position Error
  - Animation Scale Error
- `Avatar 设置`：Avatar Definition

#### 操作步骤

1. 在 Project 视图选中一个或多个模型资源
2. 勾选需要应用的参数组并设置值
3. 点击 `预览导入设置更改`。
4. 确认目标模型及参数后点击 `执行预览中的更改`。

## 使用建议

- 按钮不可用或没有执行时，先检查 Project / Hierarchy 选择、输出目录和工具底部状态；准备清单后还需点击执行按钮。
- Project 预制体批量复制与高级场景实例处理使用不同列表，按对象所在位置添加。
- 依赖检查可先导出 JSON/CSV 报告，再处理候选引用。依赖修复和非法引用替换也会先生成计划，确认后执行。
- 大批量操作可先用小范围资源验证，并提前提交版本控制。完成后检查 Console、状态栏及关键特效、动画、UI 的场景表现。
- 新增工具功能时，同步补充用途、输入、按钮、输出和限制说明。

## 恢复与限制

- 文件操作备份保存在项目的 `Library/ToolSetBackups/`，包括原内容、.meta 和新增文件记录，自动保留最近 10 份。左侧全局“恢复上次文件操作”恢复最近一次有文件变化的已完成操作；场景修改使用 Unity Undo。
- 点击恢复后会弹出二次确认，说明恢复范围、删除新建资源及还原原有文件的影响；选择“确认恢复”才执行，选择“取消”不作修改。
- 恢复前检查整批文件。操作之后再次被修改的文件会阻止恢复，避免覆盖后续工作。清理 Library 会删除这些本地备份。
- 不会强行修复无法判断类型或 fileID 的缺失 FBX 子资源。需要先恢复原文件，或在 Inspector 中明确指定目标；不能只替换 GUID 后宣称修复成功。
- 引用修复面向 Unity YAML 文件及导入器 .meta 的对象引用；二进制资源不会当作文本改写。有未保存修改的目标资产、场景、Prefab Stage 或导入设置会阻止文件替换。
- 修复依赖引用保留原 JSON 的 GUID 基线。替换 GUID 与修改文件的身份记录保存在项目 `Library/ToolSetDependencyRepairs/`，以记录内容区分，每次检查都会复查实际引用。清理 Library 会删除这份本地记录；需要跨工程携带新基线时，重新导出依赖 JSON。
- 映射遇到新增/删除节点或组件的结构覆盖时会阻止执行；请先保存为独立预制体再映射，以免丢失结构覆盖。
- 一次导入、一次高级复制模块或一次保存期间无法中断 Unity API；取消发生在步骤之间。
- 输出目录、排除目录、命名与导入参数等输入按项目保存；场景对象与上次执行计划不跨重载恢复。

## 开发与验证

普通工具面板实现 `IToolGUI` 或继承 `ToolPanel`；只有主窗口继承 EditorWindow。主窗口负责选择变化通知、滚动布局与事件释放。

共用模块：

- `ToolWorkflow.cs`：执行计划、变更检查、分帧执行、结果、备份与恢复。
- `ReferenceRepair.cs`：对象引用解析、资源类型/fileID 匹配。
- `PrefabCopyPlan.cs`：批量源列表、合并依赖复制、场景实例化及高级分步适配。
- `SceneCopyPlan.cs`：场景多选、嵌套去重、批量模块复制/保存、场景快照与 Undo。
- `CopyOverview.cs`：根副本列表、资源分类摘要、文件明细、共享资源和折叠的操作记录。
- `ToolAssetCache.cs`：项目变化时失效的搜索/依赖缓存。
- `ToolPreferences.cs`：按项目保存输入。
- `ToolUi.cs`：共用界面与分页。

在 PowerShell 中运行 `Tests~/Run.ps1`，可通过 `-UnityEditor`、`-Dotnet` 和 `-Csc` 指定安装路径。`-CompileOnly` 只编译全部源码和测试；`-FocusedTestFile` 配合 `-ExecuteMethod`、`-ResultFile` 可运行单项回归且不要求 FBX 夹具。脚本在 TEMP 下创建独立工程，不会启动当前工作工程；它输出进程 ID、日志与结果路径。完整回归需要当前工程已有 Unity.Timeline / UnityEngine.UI 编译程序集，并保留多 Mesh 测试夹具 `fish_200004005_skin.fbx`。

`Tests~` 不参与 Unity 常规资源导入。回归包含批量根预制体及变体/嵌套关系、共用资源去重、资源同名冲突、真实 FBX 多 Mesh/权重、引用与子资源匹配、模型导入器引用、保存范围、批量场景 Undo、整批失败/取消恢复、列表偏好保存及清单失效检查。验证结果见 [Tests~/Validation.md](Tests~/Validation.md)。

依赖检查专项回归：`Tests~/Run.ps1 -FocusedTestFile DependencyRecordRegression.cs -ExecuteMethod DependencyRecordRegression.Run -ResultFile dependency-record-regression-results.txt`。它不需要 FBX 夹具，覆盖已修复条目复查、JSON 中断链范围、旧版修复识别、导入器引用、移动与备份恢复、候选筛选、无效 fileID、部分修复、共用复制与清空行为。
